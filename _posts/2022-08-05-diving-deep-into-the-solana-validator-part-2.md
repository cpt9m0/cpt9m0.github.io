### Diving Deep into The Solana Validator — Part 2

#### Profiling the Solana Validator (RPC Node).

![Flamegraph of Solana Validator Runtime](https://cdn-images-1.medium.com/max/800/1*rjr5m_Srn9ltfNccZ6FkaA.png)Fig 1. Flamegraph of Solana Validator Runtime

One of the significant challenges of large tech companies is writing perfect software, not only in user experience and user interface but also in performance. In some use cases, performance is the most crucial part of the system. For instance, in banking systems or blockchain networks, transactions must be processed in a flash, and they usually face many incoming transactions to be processed.  
I believe there is no perfect software, and each can be improved in some way, i.e., using less CPU, consuming less memory, and having fewer system calls. But improving a developed software is not an easy job. The first thing we should know is which part of the software needs improvement and where the time is spent in the code. Fortunately, getting this information is relatively straightforward by using _profilers_. A _profiler_ is a form of dynamic analysis that measures memory, time complexity, frequency of function calls, and much more.

#### An Introduction to Flamegraph

The cover image (Fig 1) of this article represents an example of a flamegraph. A flamegraph visualizes where the time is being spent in the program. A flamegraph can be generated by a complicated procedure called sampling. Sampling means recording the times per second that threads in a program are interrupted, the current location in your code (based on the thread’s instruction pointer), and the chain of functions that were called to get there. In our case, the sampling will be done by a Linux tool called _perf_.  
The **y-axis** on a flamegraph shows the stack depth number. The main function of the analyzed program will be closer to the bottom, and the called functions will be stacked on top. The **width** of each box shows the total time that that function is on the CPU or is part of the call stack. If a function’s box is wider than others, it consumes more CPU per execution than other functions or is called more than other functions. The **color** of each box isn’t significant and is chosen at random.

#### Installing Perf and Flamegraph

First, you will need to install requirements on your machine [1]. If you use a Debian distribution (e.g., Ubuntu), execute the following command:
    
    
    sudo apt install linux-tools-common linux-tools-generic linux-tools-`uname -r`

Now you are ready to install the flamegraph written in the Rust programming language:
    
    
    cargo install flamegraph

The `flamegraph` binary command will be available after installation is finished. If your shell cannot auto-complete it, you enable it by manually configuring it:
    
    
    flamegraph --completions bash > $XDG_CONFIG_HOME/bash_completion # or /etc/bash_completion.d/

#### Running the Solana Validator — RPC Node

For installing the Solana CLI tool and configuring your machine to run a validator, you can refer to my previous article [2]. Create a bash script file called `validator.sh` to quickly run the validator without passing configs.
    
    
    #!/usr/bin/env bash
    
    
    set -e
    
    
    exec solana-validator \  
        --no-voting \  
        --identity ~/validator-keypair.json \  
        --known-validator 7Np41oeYqPefeNQEHSv1UDhYrehxin3NStELsSKCT4K2 \  
        --known-validator GdnSyH3YtwcxFvQrVVJMm1JhTS4QVX7MFsX56uJLUfiZ \  
        --known-validator DE1bawNcRJB9rVm3buyMVfr8mBEoyyu73NBovf2oXJsJ \  
        --known-validator CakcnaRDHka2gXyfbEd2d3xsvkJkqsLw2akB3zsN1D2S \  
        --only-known-rpc \  
        --ledger /data/solana-ledger \  
        --accounts /data/solana-account \  
        --rpc-port 8899 \  
        --rpc-bind-address 0.0.0.0 \  
        --dynamic-port-range 8000-8020 \  
        --entrypoint entrypoint.mainnet-beta.solana.com:8001 \  
        --entrypoint entrypoint2.mainnet-beta.solana.com:8001 \  
        --entrypoint entrypoint3.mainnet-beta.solana.com:8001 \  
        --entrypoint entrypoint4.mainnet-beta.solana.com:8001 \  
        --entrypoint entrypoint5.mainnet-beta.solana.com:8001 \  
        --expected-genesis-hash 5eykt4UsFv8P8NJdTREpY1vzqKqZKvdpKuc147dw2N9d \  
        --wal-recovery-mode skip_any_corrupted_record \  
        --limit-ledger-size \  
        --no-port-check \  
        --enable-rpc-transaction-history \  
        --full-rpc-api \  
        --log /data/solana-spare/logs/solana-validator.log

Note that I have mounted a 2 TB hard drive to `/data`, since for storing ledger and accounts at lease 1.5 TB is required. Now we can easily run validator by executing `validator.sh`. After executing, it will download some data from the blockchain network, and when the download is finished, it starts to validate transactions.

#### Profiling The Validator

Grab the PID after running the validator:
    
    
    ps ax | grep solana-validator

You can also see the number of threads running by this process. On my instance, 125 threads were running.
    
    
    ps -o nlwp <PID of validator>

Start profiling using `cargo-flamegraph`:
    
    
    flamegraph -- --pid <PID of validator>

This command will start to collect data and samples; run this for a short period (e.g., 20 seconds); otherwise, it can generate a huge file (more than tens of gigabytes). You can press `ctrl+c` to end sampling and generating the actual flamegraph. Here is my generated files:
    
    
    -rw-------  1 root   root   2.8G Aug  4 13:59 perf.data  
    -rw-r--r--  1 root   root   3.3M Aug  4 14:21 perf.svg

Click [here](https://drive.google.com/file/d/1URSo42ejalBxYfN4Wo1SOO2ti_2Xbllp/view?usp=sharing) to open the generated graph, download the file, and open your browser. Another way to browse and inspect the collected is using `perf` commands [3].
    
    
    perf report

I want to end this article with this sentence from the flamegraph repository [1]:

> Flamegraphs Are the Beginning, Not the End. Flamegraphs show you the things that are taking up time, but they are a sampling technique to be used for high-level and initial looks at the system under measurement. They are great for finding the things to look into more closely, and often it will be obvious how to improve something based on its flamegraph, but they are really more for choosing the target to perform optimization on than an optimization measurement tool in itself.
